## 1. 现状评估（四个维度）

### 1.1 布局结构 —— 底子好，有两处结构性债

**做对的地方**

- 移动端滚动架构是正确解：`html/body/#root` 锁高 `overflow:hidden`，滚动下放到 `.main-content`，底部胶囊 `position:fixed`。这从根上规避了 Android WebView 在 body 惯性滚动时 `fixed` 元素跟随位移的老问题（`client/src/styles/global.css:241-291`）。
- 沉浸页用 `.mobile-nav-hidden` 在祖先节点上标记，同时回收为胶囊预留的 96px 内边距，`hide/show` 两条路径对称。

**问题**

1. **桌面三列 grid 用手写像素补偿**：`HomePage.module.css:23-28` 的 `.feed { left: 18px }`，注释自己承认「改导航宽度/列间距/内边距/帖子最大宽时需同步调整」。这是一个没有测试保护的隐式耦合，任何一次改版都可能让帖子栏偏离视觉中线。
   → 建议改为 `justify-content: center` + 让左右列等宽（`minmax(280px, 1fr)` 已是等宽，问题出在左导航 220px 的占位与不对称内边距 16/44），把不对称内边距改成对称后即可删掉 `left`。
2. **胶囊导航预留高度硬编码**：`.main-content` 的 `padding-bottom: calc(96px + safe-area)` 与胶囊实高 68px + 浮起 16px 强耦合，散落在 `global.css` 与 `Sidebar.module.css` 两处。
   → 建议提取 `--nav-capsule-h: 68px` / `--nav-capsule-gap: 16px`，两处都引用。
3. **沉浸页判定规则分散**：`HIDE_MOBILE_NAV_PATHS` 正则 + 组件状态两套机制写在 `MainLayout` 里，新增沉浸页容易漏。
   → 建议收敛为一个 `useImmersive()` hook，或让路由配置携带 `immersive: true`。

### 1.2 组件规范 —— 本次最大的问题面

**圆角：全项目 18 种取值**
`2 / 4 / 6 / 8 / 9 / 10 / 12 / 14 / 16(var) / 17 / 18 / 19 / 20 / 22 / 24 / 999 / 50% / 0`

同类组件彼此不一致的例子：

- 内容卡片：`PostCard` 22px · `RecommendCard` 22px · `ExplorePage` 20px · `--radius` 16px
- 列表行：`ConversationItem` 9px · `ConversationSidebar` 17px / 19px · `ChatContextMenu` 10px
- 输入框：`AdminPage` 6px · `LoginPrompt` 4px · `BookDetailPage` 8px

**字号：14 档且语义撞车**
`10 / 11 / 12 / 13 / 14 / 15 / 16 / 17 / 18 / 20 / 22 / 24 / 28 / 36`
「正文」同时存在 14px 与 15px 两档（`AdminPage` 用 14、`PostCard.caption` 用 14、`PostDesc` 用 15），无法从字号判断信息层级。

**动效时长：0.12 / 0.15 / 0.16 / 0.18 / 0.2 / 0.3s 混用**，缓动基本只有 `ease`，无令牌。

**描边用硬编码 rgba 冒充令牌**：

- `rgba(210,221,210,0.9)`（`PostCard` 浅色描边 = `--border-color` 的 alpha 版）
- `rgba(38,43,53,0.95)`（深色描边）
- `rgba(47,93,80,0.22)`（`PostCard.followBtn`）、`rgba(201,169,98,0.38)`（深色）
- `rgba(255,255,255,0.14)`（胶囊描边）

这些本质是「描边令牌拆了 alpha」，应提升为 `--border-subtle` / `--accent-border`。

**空令牌**：`--bg-secondary` 浅色等于 `--bg-primary`(#ffffff)、深色等于 `--bg-hover`(#1e232d) —— 它目前不承担任何语义。

### 1.3 交互流程 —— 主要靠逐处补丁

| 现象                   | 现状                                                                                  | 建议                                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 触屏 sticky hover 残留 | 在 `Sidebar.module.css` 用 `@media (hover:hover)` + 显式 `.active:hover` 覆盖修了两处 | 全局统一：所有 hover 规则包进 `@media (hover: hover)`，并约定「选中态写在 hover 规则之后」 |
| 键盘焦点               | 只有 `.sidebar :focus-visible` 有 inset 焦点环                                        | 补齐全局 `:focus-visible { outline: 2px solid var(--focus-ring); outline-offset: 2px }`    |
| 选中态表达             | 胶囊导航靠 26→28px 图标 + 文字色变化                                                  | 改为「实心强调底 + 图标反色」（见 §3.3）                                                   |
| 双击 Tab 回顶          | 350ms 阈值隐式手势，无视觉反馈                                                        | 保留手势，回顶时给一个轻量 toast 或滚动动效                                                |
| 加载/空/错三态         | `EmptyState` 组件已存在但只有部分页面接入                                             | 逐页补齐 loading / empty / error                                                           |

### 1.4 视觉层次 —— 卡片「浮」不起来

毛玻璃卡片 `--bg-frosted`（浅 `rgba(255,255,255,.62)` / 深 `rgba(28,32,42,.58)`）+ `blur(18px)` 压在**同色系的页面底**上，实测合成后：

- 浅色：卡片 `#f9faf9` vs 页底 `#eef2ee` = **1.08:1**
- 深色：卡片 `#161921` vs 页底 `#0d0f14` = **1.09:1**

1.08:1 意味着人眼几乎无法分辨边界，信息流的「块感」全靠 1px 描边（1.24:1）撑着。

**根因**：毛玻璃被用在了「正文卡片」——它本该只服务**浮层**（导航胶囊、模态、下拉菜单），因为这些地方有内容从底下穿过，毛玻璃才有意义。正文卡片下面是纯色页面底，模糊等于什么都没做，只白白牺牲了对比度。

### 2.3 两处需要搬去「代码里」的修正

1. **角标文字** —— `Sidebar.module.css` 的 `.badge { color: white }` 在深色下（`--danger` = `#E0586B`）只有 **3.63:1**。改用 `--on-accent`：浅色 5.35:1、深色 5.27:1，两主题同时达标。

## 3. 分模块问题与改进建议

### 3.1 首页信息流

**问题**

- 卡片毛玻璃导致层次塌陷（§1.4）。
- 点赞状态表达有缺陷：`PostCard.module.css:251-253` 的 `.actionBtn:first-child { color: var(--danger) }` 与 `:261-263` 的 `.actionBtn.liked { color: var(--danger) }` **颜色完全相同**，未点赞与已点赞只差 svg 的 `fill`。用户在快速滑动时容易误判自己点没点过。
- 图片轮播容器 `background: #000` + `object-fit: contain`：横图上下会出现纯黑留白，在浅色主题里是一块突兀的黑矩形。

**建议**

1. 卡片改回 **实心 `--surface` + 阴影**，毛玻璃只留给浮层。仅在卡片上保留 `--shadow`（浅 `0 6px 20px rgba(31,60,48,.06)` 偏弱，建议提到 `rgba(31,60,48,.08)` 并加一层 2px 近距阴影做边缘定义）。
2. 点赞三态明确化：
   - 未赞：图标描边 + 文字均用 `--text-secondary`
   - 已赞：图标实心 + 文字均用 `--danger`
   - 按下瞬间：`transform: scale(.92)` 微反馈
3. 图片容器底色改为 `--surface-sunken`，横图留白与主题一致；视频封面同理。

### 3.2 消息会话

**问题**

- 会话行的「时间 + 未读角标」竖排右对齐，但角标是 `padding: 0 4px` 的 hug 宽，1 位与 2 位数字宽度不同导致右侧参差。
- 未读数没有上限（`99+` 未处理）。
- `ConversationItem` 圆角 9px 与 `ConversationSidebar` 17/19px 不成体系。

**建议**

1. 角标最小宽度 18px + 居中，9 以上显示 `99+`。
2. 行圆角统一 `--radius-row`（14px）。
3. 列表行 hover 只在 `@media (hover:hover)` 生效（触屏 sticky hover 目前靠逐处补丁）。

### 3.3 底部导航胶囊（本次重点改造项 · 已定稿）

**改造前**：`max-width: 420px` 的胶囊里最多塞 7–8 项（首页/消息/分享/公告/图书/语音/主页 + 管理），移动端 `display:none` 掉所有文字标签，仅留 26px 图标（选中 28px）。单项可用宽度约 50px，已低于舒适的 44×44 触控目标，且选中态只有 2px 尺寸差 + 颜色变化。

**已定稿方案：压到 5 项，并把文字标签加回来。**

| 项                               | 处理                                                                                                        |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 首页 / 消息 / 图书 / 语音 / 主页 | 保留为 5 个顶层入口，**恢复 11px 文字标签**（胶囊高 64px，单项可用宽度约 70px）                             |
| 分享                             | 移出导航 → 首页右下角 **56px 悬浮按钮（FAB）**，浮在胶囊之上、不遮挡；按钮底 `--accent`、图标 `--on-accent` |
| 公告                             | 移出导航 → 消息页「会话 / 通知」分段已有归属，主页菜单作为二级入口                                          |
| 管理                             | 移出导航 → 主页（个人中心）二级菜单，仅管理员可见                                                           |

**形态：悬浮胶囊 + 毛玻璃，内容从它旁边和底下透出**

胶囊**不占布局空间**（绝对定位在屏幕底部 `y = 844 - 101`），滚动内容直接铺到屏幕底边。因此：

- 内容会在胶囊**左右 21px 的留白**和**胶囊上方**继续可见 —— 这正是悬浮导航该有的样子，而不是「一条把内容切断的实心栏」；
- 胶囊本身带 `--frosted` 底 + `backdrop-blur(18px) saturate(180%)`，穿过的内容会真正被模糊掉，毛玻璃才成立。

> 实现要点：`--frosted` 的不透明度要足够低（浅色 0.66 / 深色 0.72）才看得出玻璃感；但不能再低，否则 `textMuted` 标签在深色下会掉出 4.5:1。滚动容器要留足底部内边距（约 101px + 安全区），保证最后一条内容不会被胶囊盖住。

**尺寸**

| 项                 | 值                                                                                                                                                                                                           |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 胶囊高 / 圆角      | 68px / 34px（全圆）                                                                                                                                                                                          |
| 单项宽 × 高 / 圆角 | 约 70px × 58px / 29px                                                                                                                                                                                        |
| 图标               | **直接复用项目里 lucide-react v0.511.0 的原始图标**（`House` / `MessageCircle` / `BookOpen` / `AudioLines` / `User`），输出 20px。不要手工重绘 —— 手绘版线条比例与 lucide 的 24 网格不一致，放大后差异很明显 |
| 标签               | 11px Medium                                                                                                                                                                                                  |
| 角标               | 15×15，**压住图标右上角约 12px**（不是并排在旁边）                                                                                                                                                           |

**选中态** —— 「实心强调底 + 图标与标签反色」：

- 浅色：墨绿实心块 + 近白图标/文字
- 深色：鎏金实心块 + 近黑图标/文字（靠 `--on-accent` 令牌自动反色）

> ⚠️ **注意**：accent 的明度在两个主题间是**反相**的（浅色 accent 是深绿，深色 accent 是浅金），所以「实心 accent 底 + 单色图标」的选中态必须让图标跟随 `--on-accent` 走。实现层用一份 CSS 变量即可，但**不要**用固定 white 图标 —— 那在深色只有 3.6:1。

**角标**：底色 `--danger`、文字 `--on-accent`。原来放在 24×24 图标容器内 `y:-7` 会溢出，而 **frame 默认 `clipsContent: true`**，角标会被裁成月牙 —— 需把容器放宽（30×28）并把角标收进边界内，让它自然压住图标右上角（见 §3.4 麦位状态点的同类修复）。

**子页面高亮映射**（二级页面按所属一级页高亮；真正的三级页面隐藏导航）

| 页面                                    | 导航状态                                    |
| --------------------------------------- | ------------------------------------------- |
| 首页信息流 / 搜索发现                   | 高亮 **首页**                               |
| 图书列表                                | 高亮 **图书**                               |
| 语音 · 房间列表                         | 高亮 **语音**                               |
| 消息会话 / 公告                         | 高亮 **消息**                               |
| 个人主页 / 管理后台                     | 高亮 **主页**                               |
| 登录弹层（覆盖态）                      | 背后仍显示导航（高亮 **首页**），被遮罩压暗 |
| 图书详情 / 阅读器 / 语音房内 / 发布弹层 | **不显示导航**（沉浸）                      |

> 判定规则建议落到路由配置上：每个路由带 `navKey`（高亮哪一项）+ `immersive`（是否隐藏导航），而不是靠路径正则散判 —— 现在 `MainLayout` 里的 `HIDE_MOBILE_NAV_PATHS` 就是后者，容易漏。

> ⚠️ **做图标时的两个必踩坑**
>
> 1. **容器裁切**：图标容器是定尺寸 frame 且**默认 `clipsContent: true`**，而 SVG 描边中心线画在边界上时，外半侧会溢出约 `strokeWidth/2` —— 24px 图标放进 24px 容器**会被裁掉一圈**，看起来像「图标被遮住 / 超出范围」。规则：**容器要么留 2–3px 余量，要么显式 `clipsContent: false`**。
> 2. **矢量偏移导致不居中**：把 SVG 解析出的 VECTOR 放大（改 width/height）时，它的 `x` / `y` **会保留原有的偏移量**。本次就出现「矢量落在 (4,4)、视觉重心偏右 4px」——表现正是「图标跟文字没有居中对齐」。规则：**改完尺寸后必须同时把矢量的 x/y 归零**，否则它在容器里是歪的。这类问题肉眼在缩略图上看不出来，要读几何值才能确认。

## 6. 设计稿说明

设计稿 `K App 双主题 UI 优化基线`（Ardot）：https://ardot.tencent.com/file/725358303671695

**13 个页面 × 2 套主题 = 26 屏**；浅色在上、深色在下，同一列即同一页面的双主题对照。

```
标题区
├── 浅色主题区 · 青瓷黛绿
│   ├── 第 1 行  首页信息流      · 搜索发现      · 图书列表
│   ├── 第 2 行  图书详情(沉浸)  · 阅读器(沉浸)  · 消息会话
│   ├── 第 3 行  语音·房间列表   · 语音房内(沉浸)· 个人主页
│   ├── 第 4 行  公告            · 管理后台
│   └── 第 5 行  登录弹层        · 发布弹层
├── 深色主题区 · 玄夜鎏金        （同样 13 屏，变量模式切换）
│   └── 第 1–5 行（同上）
└── 组件规范区
    ├── 组件源            会话行 · 麦位 · 导航胶囊 · 状态图标（4 个可复用组件）
    ├── 一 · 色彩令牌与实测对比度    6 行双主题色块 + 实测比值
    ├── 二 · 圆角 / 字号 / 间距尺度
    └── 三 · 核心组件 · 双主题对照
        ├── 按钮：主 / 按下 / 禁用 / 幽灵 / 危险
        └── 输入 / 状态：输入框默认 · 聚焦 · 点赞两态 · 数字角标
```

### 关键实现方式：变量驱动，而非两份硬编码

- **`Colors` 变量集**：21 个色彩 token，每个含 `Light` / `Dark` 两个模式。
- **`Scale` 变量集**：17 个尺度 token（圆角 6 档、字号 6 档、间距 5 档），单模式。
- **主题切换靠 mode override**：深色主题区挂了 `Colors → Dark` 的模式覆盖，其下所有屏幕自动解析为深色。选中任一主题区改模式，整块实时翻转 —— 这正好对应代码里的「一份 CSS 变量 + `[data-theme]` 覆盖」。
- **图标也走变量**：导航图标、状态栏图标、动作图标、工具图标的描边色全部绑定到 `$:Colors:*` 令牌（而不是 SVG 里的写死色值）。这样深色版不需要任何额外资产 —— 这也是为什么文字标签与图标在两个主题下都能自动反色。
- **4 个可复用组件**：会话行、麦位、导航胶囊、状态图标。导航胶囊与状态图标被 12 屏复用，是改版的单一改动点。

> 设计稿里唯一「画不出变量」的是 `G()` 图片占位（灰色带标签的方框）——那是图片位，实现时由真实图片替换。

## 7. 遗留与待确认

1. **accent 明度反相**（§2.3.2）—— 这是配色的固有属性，不是缺陷。但如果将来要做「实心 accent 底 + 单色图标」的组件（如 FAB、选中态卡片），图标必须跟 `--on-accent` 走而不是固定白色 —— 深色下白字只有 3.6:1。
2. **阅读器主题独立性**（§3.5）—— 建议阅读器有独立的阅读主题，不跟随 App 主题。这会让令牌体系多一个维度，需要你确认方向。
3. **导航改版后仍待真机验证的量** —— 5 项导航在真机上单项宽约 70px、图标 24px + 标签 11px，触控目标是达标的；但两处手感需要真机走一遍：①「分享」被挪成 FAB 后的入口发现性（FAB 与胶囊间距按 16px 留）；②胶囊改成绝对定位悬浮后，**滚动容器的底部内边距要留够 101px + 安全区**，否则最后一条内容会被胶囊永久盖住（设计稿是静态截图，看不出这个问题）。
4. **对比度脚本**放在 `.workbuddy/tmp/`（非交付物），如需长期使用建议移到 `e2e/` 或 `scripts/` 并加进 CI，让令牌改动能自动校验对比度。
