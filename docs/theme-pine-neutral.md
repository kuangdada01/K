# K App 配色改版方案 — 松绿 + 黑白中性（Pine & Monochrome）

> 范围：**全端**（Web 客户端 + Android 原生 Compose 层 + 静态资源/启动图标 + 邮件模板核对）
> 目标：主题色统一 `#325D51`，语义色只保留红色，其余元素只用黑 / 白 / 中性灰阶；
> 浅色与深色双主题均满足 WCAG AA（正文 4.5:1，深色主题色文字 ≥6.6:1）。
> 取代：《K App 双主题 UI 优化方案》中的配色章节（「青瓷黛绿 / 玄夜鎏金」两套色板）。
> 落地状态：**已实施**（2026-10-12），验证截图见文末 §7。

## 1. 核心设计决策

### 1.1 为什么「填充用 #325D51、深色文字用 #7FB5A2」拆成两个令牌

`#325D51` 在深色底（`#121212` / `#1C1C1C`）上的对比度只有 **2.29–2.59:1** —— 作为
按钮填充没问题（内部白字 7.45:1 承载可读性），但作为**直接落在深底上的文字/图标/描边**
（链接、选中项文字、图标 tint、已关注描边）不可读。因此拆成一对令牌：

| 令牌            | 用途                                       | 浅色      | 深色                               |
| --------------- | ------------------------------------------ | --------- | ---------------------------------- |
| `--accent`      | 填充：主按钮底、选中底、徽标、进度条、开关 | `#325D51` | `#325D51`（与浅色同值）            |
| `--accent-text` | 前景：链接、图标、选中项文字、强调描边     | `#325D51` | `#7FB5A2`（同色相 H≈160°，提亮档） |

`#7FB5A2` 是从 `#325D51` 同色相提亮得到的最相邻档位，保证「看起来还是同一个绿」。
全局共 136 处 `var(--accent)` 引用按此规则分流：69 处填充保持原令牌，
67 处前景（color / border-color / stroke / fill / outline / 焦点环）改用 `--accent-text`。

### 1.2 为什么红字徽标改用 `--on-danger`

改版前深色 `--danger #E0586B` 上用 `--on-accent`（深字）凑对比度；改版后
`--on-accent` 两主题统一为白色，红底必须自带反相令牌：浅色白字（5.65:1）、
深色深字 `#121212`（5.15:1）。全站唯一红底文字处（侧栏未读角标）已切换。

### 1.3 例外清单（刻意保留，不计入「黑白灰」约束）

| 例外                                                                   | 理由                                                                                              |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 棋盘木色盘面 + 朱红/墨黑棋子（`ChessBoard.tsx` / `ChessBoardView.kt`） | 「棋盘是实物」的既定设计决策，两主题同一观感；黑方棋子由蓝灰 `#2C3440` 修正为**中性黑 `#262626`** |
| 地图（OSM 浅色瓦片）上的图钉/路线                                      | 固定浅底道具，标记使用 `#325D51` 原值（提亮档在浅底上反而不可读）                                 |
| `--danger` 红色全家（含红心点赞、删除、绝杀红光）                      | 按需求保留红色；红心点赞图标的红与「警告红」共用 `--danger`                                       |
| 服务器邮件模板（`server/src/mailer.ts`）                               | 核查后本就为中性灰阶，无需改动                                                                    |

1. **令牌完整性**：全仓 `var(--x)` 引用与 `global.css` 定义逐一对账，无悬空引用（唯一例外为运行期注入变量与带兜底的双保险写法）。
2. **残留扫描**：对 50+ 个旧色值（浅绿/鎏金/蓝调黑全家）全仓正则扫描，客户端与 Android 源码零残留（历史注释除外）。
3. **对比度实测**：34 组前景/背景配对脚本核验，全部 ≥4.5:1；深色主题色文字 ≥6.68:1；主题填充白字 7.45:1。
4. **端到端目检**：构建产物 + 隔离数据库启动，Playwright 截取浅/深两套共 20 张关键界面（首页登录/未登录、登录/注册弹窗、发布器、探索、图书、语音、消息、主页、公告），逐一核对主题色/中性灰/红色语义/深色可读性。
   **留档截图**：`docs/ui-verify/web/05–12-…-松绿中性.png`（8 张，浅深对照）。
