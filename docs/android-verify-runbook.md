## 0. 准备（先跑前置检查，再拿手机）

```bash
# ① 前置检查：10 秒查清"服务器是否就绪"（不需要手机）
npm run android:preflight

# ② 连上手机后：一条命令做完可脚本化的那部分（安装/版本/启动/崩溃/页面加载/首帧/权限/截图）
npm run android:device-check        # 会先跑一遍①，未就绪会直接告诉你先解决什么

# ③ 交互类项目照本手册往下点（Hero 转场、沉浸、指纹、画中画、后台麦克风等）
```

`android:device-check` 会在 `android/build/device-check/` 留一份报告（md + 截图），**把它发我即可**，
里面有过滤后的关键日志与"上次退出原因"。

手工备选：

```bash
# 安装（覆盖安装用 -r；本版是新包名，首次安装不冲突）
adb install -r release/k-app-0.1.0-release.apk

# 看日志（按 tag 过滤，一次开好这个窗口再开始点）
adb logcat -s KHost KWebView KChrome KTheme KDownload KNotify KPlayback \
              KBiometric KDeviceInfo KDiagnostics KImageCompress KSave KShare KNativeBridge

# 想从零验（清掉登录态与缓存）
adb shell pm clear top.kuangdada.k
```

**三个必须先解决的前提**（`npm run android:preflight` 会逐条替你查）：

1. 服务器 `.env` 的 `ALLOWED_ORIGINS` 必须含 `https://appassets.androidplatform.net`，
   且改动后 **`pm2 delete + start`**（`restart` 不重读 `.env`）。**漏了这一步，App 内所有 API/SSE 都会 403**，
   现象是"能打开但处处报网络错误"；
2. 服务器 `.env` 的 `APP_VERSION` 必须是 `0.1.0`。若还留着旧版号（如 `0.2.48`），**新 App 会弹"发现新版本"**
   并去下载那个**另一个 applicationId 的旧包**（装上会出现两个图标）；
3. 新版 APK 必须真的在服务器上（`/apk/k-app-0.1.0-release.apk`）。注意 nginx 对不存在的路径会回退
   `index.html`，**状态码仍是 200**，所以要看体积而不是状态码 —— 前置检查里已经按体积判断。

> 当前实测（最后一轮）：这三条**都还没满足**（服务器仍返回 403、仍广告 `0.2.48`、APK 未上传）。
> 因为它们都靠 `deploy.ps1` 一次性解决（打包 dist + `.env` + 单独上传 APK），所以顺序是：
> **先 `deploy.ps1` 部署 → 再 `npm run android:preflight` 确认全绿 → 然后开始真机验收。**

## 3. 看图（一期 A 类，行为规格见 `docs/native-image-viewer.md`）

在信息流卡片/帖子详情多图里逐条过：

1. **打开不闪**：点图 → 从缩略图位置放大进入，中途不出现"黑屏+转圈闪一下"
2. **退出回弹**：翻到第 3 张再退出 → 图片从全屏**缩回第 3 张缩略图**，背景全程纯黑；返回键/单击/右上角关闭三条路径一致
3. **下滑退出**：1x 下拉跟手、背景纯黑；超过约一指节（或快速下滑）松手退出，不足则弹回
4. **单击退出**：1x 单击退出；放大态单击先缩回 1x
5. **放大退出**：双指放大/拖动后按返回，飞行起点是**眼睛看到的位置**（不跳）
6. **返回键一次退出**（不是按两次）
7. **EXIF**：相机竖拍照片正立
8. **鉴权图**：私信/私密图片正常加载
9. **失败退化**：断网时显示"图片加载失败"，不崩
10. **应急开关**：`localStorage.k_viewer_hero='off'` 后刷新 → 退化为淡入（用于区分 Hero 问题还是查看器问题）

> 画廊/详情退出后，**主轮播应停在刚才看的那一张**，回首页卡片也同步。

>
> **另外（实测发现，非本 App 代码问题）**：ColorOS / 一加等 ROM 在「清理后台」时会**连带清掉该 App 的通知**，
> 所以"杀进程后点通知栏那条通知"这类路径在这些机型上根本不存在。冷启动深链已改成不依赖通知的
> 验证方式（`ACTION_VIEW` / `ACTION_SEND` 意图），也就是上面 11.3 的自动化检查。
>
> **分享文本规则（产品约定，非缺陷）**：`ACTION_SEND` 进来时，只有**文本本身就是站内链接**才跳转；
> 像"看看这个 https://…/post/99"这种**链接夹在文字里**的，当前行为是**复制并提示**（不跳转）。
> 若希望"夹带评论的分享也直接跳"，说一声即可改（抽出文本里第一个站内链接 → 路由）。

## 13. 已知边界（不是 bug，先别当问题报）

- **两个 App 图标**：新包名 `top.kuangdada.k` 与旧 `com.k.app` 无关系，可共存；旧包已弃用。
- **屏幕共享**：受 WebView 能力限制，见 §6 结尾。
- **深链会弹系统选择器**：没做 `assetlinks.json` 免验证（需服务器配合，属独立项）。
- **「分享到 K」的图片**：目前只提示，直接发帖需原生选取 + 上传通道（独立项）。
- **「拍照」快捷入口**：原生侧已支持（且已声明包可见性 `<queries>`），但网页侧的 file input 目前没有
  `capture` 属性，所以选图时不会直接出现"拍照"入口；要启用只需给对应 input 加 `capture`（属网页改动）。
- **离线推送**：App 被杀后收不到通知（当前是"后台仍连着 SSE"这一段能收到）；真·离线推送需 FCM/厂商通道（独立项）。
- **锁屏播放控制**：通知栏有「停止」，但没有播放/上一首/下一首（需要 `MediaSessionCompat`，独立项）。
