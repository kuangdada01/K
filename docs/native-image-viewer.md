# 原生图片查看器（方案 B）设计与联调清单

> 目标：把「全屏看图」从 WebView 里搬出来，换成和微信朋友圈 / 酷安 / 小红书 /
> 系统相册同一套做法（原生 View + 原生手势），彻底摆脱 WebView 在跟手与掉帧上的天花板。

## 1. 为什么必须做成原生

| 层          | WebView 方案                                 | 原生方案（本实现）                                                       |
| ----------- | -------------------------------------------- | ------------------------------------------------------------------------ |
| 谁搬像素    | Chromium 合成器（原生滚动）/ JS（transform） | RenderThread 直接绘制                                                    |
| 手势 → 画面 | 触摸事件跨到网页层再回写                     | 原生 `ScaleGestureDetector` / `GestureDetector` / `ViewPager2`，无跨语言 |
| 惯性/回弹   | 浏览器滚动物理（上一版才拿到）               | `ViewPager2`/`OverScroller` 原生物理                                     |
| 打开/关闭   | 只能做淡入淡出                               | Hero 共享元素转场 + 下拉关闭                                             |
| 大图解码    | 网页层解码 + 合成层纹理                      | 原生采样解码 + `LruCache`，按屏幕尺寸解                                  |

结论：WebView 已经做到它的上限（见 0.2.42 的原生滚动分页），再往上只有原生。

## 2. 组成

### 原生（`client/android/app/src/main/java/com/k/app/`）

| 文件                           | 职责                                                                         |
| ------------------------------ | ---------------------------------------------------------------------------- |
| `ImageViewerActivity.java`     | 查看器宿主：ViewPager2 翻页、计数、关闭按钮、Hero 打开动画、下拉关闭编排     |
| `ZoomableImageView.java`       | 手势核心：捏合 1x–4x、放大后平移（边缘钳制）、双击缩放、1x 纵向拖拽关闭      |
| `ImageLoader.java`             | 异步采样解码 + `LruCache` + 自定义请求头 + EXIF 方向校正                     |
| `NativeImageViewerPlugin.java` | Capacitor 插件桥：`open({images,index,headers,rect})` → `{index}`、`close()` |

关键设计：

- **缩放与翻页互斥**：放大态 `requestDisallowInterceptTouchEvent(true)`，翻页交还 `ViewPager2`；
  1x 时横向手势不截断，正常翻页。
- **下拉关闭**：仅 1x 且纵向为主时进入，位移跟手、幕布同步变淡；
  松手时「位移超过 min(80dp, 屏高 10%)」或「快速下滑（>1100 px/s）」即关闭，否则回弹。
- **点一下退出**：1x 单击（等过双击窗口、确认没有第二下）退出查看器；放大态单击先缩回 1x
  （原生相册的行为）。用 `onSingleTapConfirmed`，因此不会把「双击放大」吞成退出。
- **Hero 打开**：JS 传来被点缩略图的屏幕矩形 → 先在该矩形画这张图，再动画到「等比铺满」目标矩形，
  同时幕布由透明渐入；解码未及时完成（>1.5s）则退化为淡入（不阻塞打开）。
  Hero 落位后**不立刻撤掉**：等页面自己把图画好再一次性交接（同一 URL，必然命中内存缓存），
  避免「撤掉 Hero 后页面还没解码 → 闪一下黑/转圈」。
- **返回索引**：计数与返回给网页层的索引都跟随 `onPageScrolled`（拖动中按「离哪张更近」判定），
  所以「滑到一半按返回」也不会返回上一张的索引；右上角关闭按钮同样走带结果的收尾。
- **EXIF**：相机竖拍照片原生解码不校正会躺倒（WebView 是正的），必须处理。

### 网页层

| 文件                                       | 职责                                                                      |
| ------------------------------------------ | ------------------------------------------------------------------------- |
| `client/src/lib/nativeImageViewer.ts`      | 能力探测（仅原生 Android 且插件已注册）+ 调用封装；不可用/失败返回 `null` |
| `client/src/components/post/PostMedia.tsx` | 点击图片/放大按钮时优先走原生；`null` 回退现有 Web 覆盖层                 |

设计要点：

- **可回退**：插件不可用（网页端、桌面）或原生调用抛错 → 自动回退 Web 覆盖层，看图能力不会整体失效。
- **不叠加 UI**：原生接管时不渲染 Web 覆盖层。
- **索引回传**：用户可能在原生里翻过页，关闭后按返回的 `index` 同步详情页主轮播与索引。
  这条链路一共三段，缺一段就会出现「退出后不是同一张」：
  1. 原生 `ImageViewerActivity` → 插件 `{index}`（拖动中跟踪 + 关闭按钮也必须带结果）；
  2. 插件 → `PostMedia`（`setCurrentImageIndex` + `syncMainCarousel`，拿不到宽度就什么都不做，
     否则 `setOffset(0 * index)` 会把主轮播悄悄拽回第一张）；
  3. 详情页关闭 → `HomePage` → `PostCard`（`imageSync {index, seq}`：**带自增序号**，
     因为连续两次都停在第 3 张时只比索引会被判成「没变化」而漏掉同步）。
- **鉴权**：`/api/` 开头的图片需要 `Authorization`，由 JS 从 `localStorage.k_token` 取出并传给原生
  （`<img>` 无法自定义请求头，原生 HTTP 请求可以）。

### 网页层轮播（信息流卡片 / 详情页主轮播）

原生滚动分页（`client/src/hooks/snapScroll.ts`）除了停靠校正，还负责把「当前第几张」上报给
消费方（指示点、主轮播同步）。真机反馈过的两个坑都在这里修掉：

- 上报**不依赖触摸状态机**：以前把上报放在「手指已抬起」之后，`pointer` 状态一旦没清干净
  就永久不再上报 —— 现象是「滑动图片下面的点不跟随更新」；
- 触摸状态**按来源分开跟踪**：Chromium 把手势判定为原生滚动后会立刻补发 `pointercancel`
  （此时手指还按着），共用一个布尔量就会在拖动中途误判成抬手，于是「拖动中禁止程序化滚动」
  的保护失效、消费方回写位置把用户正在拖的那一页拽走 —— 现象是「连续翻页会自己滚回去、
  一次只能翻一页」；
- 「一次手势最多翻一页」的硬钳制已停用（`clampPageStep` 保留但不再调用）：连续两次快滑时，
  第二次手势开始前上一次停靠可能还没结算，钳制基准过期就把用户滑到的第 2 页硬拉回第 1 页。
  现代 WebView 的 `scroll-snap-stop: always` 已经保证「一次甩动最多一张」。

## 3. 已覆盖 / 未覆盖

已覆盖：

- 帖子详情的多图全屏查看（`PostMedia`）——多图翻页 + 缩放 + 下拉关闭 + Hero；
- 聊天图片查看器（`ChatZoomOverlay`）——原生可用时不渲染 Web 覆盖层，原生关闭后回调父级卸载；
- 私密文件夹全屏（`PrivateFolder`）——同上；列表里混有「还没上传」的 `blob:` 预览时
  自动回退 Web 覆盖层（原生是普通 HTTP 抓图，拿不到 WebView 进程内的 blob）。

鉴权头由 `authHeadersFor()` 统一生成（只有列表里出现 `/api/` 图片才附加），
三处调用方共用，避免各写一份。

暂未覆盖（下一阶段）：

- 关闭时的**反向** Hero（飞回缩略图）：目前关闭是「下拉滑出/淡出」。反向 Hero 需要网页层
  提供目标缩略图的实时位置，等首轮真机联调确认正向 Hero 的表现后再加。

## 4. 真机联调清单

装 0.2.47 后请重点确认（上一轮真机反馈的 6 条逐条对应）：

1. **打开不闪**：点详情页图片 → 从缩略图位置平滑放大进入，中途不出现「黑屏/转圈闪一下」
   （Hero 解码上限 1.5s，且等页面画好才交接）；
2. **连续翻页**：首页卡片与详情页主轮播连续快滑两次、三次，是否都如实翻过去，
   不再「自己滚回上一页」；
3. **下拉关闭**：1x 下拉 → 跟手、背景变淡；**拖过约 80dp（约一指节）或快速下滑就关**，
   不再需要拖到 1/4 屏；不足则回弹；
4. **点一下退出**：1x 单击（等过双击窗口）直接退出全屏；放大态单击先缩回 1x；
   返回键也应当**一次**就能退出（状态栏隐藏、导航栏保留，返回手势不再被系统先吃掉）；
5. **指示点跟随**：首页/详情的图片轮播，滑动过程中（手指还没松）下面的点就跟着变；
6. **退出后同一张**：从原生查看器退出（返回键 / 点一下 / 下拉 / 右上角关闭按钮四种方式），
   详情页主轮播都停在刚才看的那张；再关掉详情页，首页卡片也停在同一张；
7. **EXIF**：相机竖拍的照片是否正立（这是原生解码最容易躺倒的地方）；
8. **缩放细节**：双指捏合围绕手指中点跟手；放大后单指拖动只平移图片、不翻页；
   双击放大到 2.5x（以双击点为锚），再双击缩回 1x；
9. **鉴权图**：私信/私密图片若已切原生，是否正常加载（未切则为 Web，不受影响）；
10. **失败退化**：弱网/超大图时是否显示「图片加载失败」，且不崩不卡死。

已知风险（重点关注）：

- `ViewPager2` 与自绘手势的边界（放大态翻页、1x 时纵向拖动）在部分机型上可能过灵/过钝；
- Hero 的**等待**：原生解码是一次独立请求（WebView 的图片缓存不共享），首次打开可能要几百毫秒。
  已做「落指立刻把幕布压到 0.35（有反馈）+ 1.5s 内没解码好才退化为页内加载指示」，
  所以最坏情况是「淡入 + 转圈」，不会出现空等、也不会中途切黑闪一下；
- 完整 GIF/动图在原生侧按静态图解码（WebView 会动），如有需求再单独处理。

## 5. 发布前自查修掉的「一测就露馅」问题

| 问题                               | 症状                                                                                                             | 处理                                                                                             |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 放大态拖动被 ViewPager2 抢走       | **放大后拖动变成翻页**（`requestDisallowInterceptTouchEvent` 每次 ACTION_DOWN 会被系统复位，只在捏合时设过不够） | 落指即截断（`isZoomed()`）+ 平移时再截断一次                                                     |
| 上滑也能关闭                       | 与微信/系统相册不一致                                                                                            | 只认下拉（`dy > 0`）才进入并提交关闭                                                             |
| 大图解码 OOM                       | 4000×3000 相机原图按 `inSampleSize=1` 解码 ≈ 48MB                                                                | 采样加「4MP 像素预算」上限，同类图落到约 2000×1500                                               |
| Hero 起点依赖 `WebView.getScale()` | 该 API 语义含糊，异常值 → 从错误位置放大                                                                         | 改由网页层用 `devicePixelRatio` 换算成物理像素传过来，原生不再猜；并做量级校验，离谱即退化为淡入 |

## 5.1 真机反馈（0.2.46 → 0.2.47）

| 反馈                                          | 根因                                                                                                                                                         | 处理                                                                                                           |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| 从缩略图放大进入有闪烁                        | Hero 解码上限只有 180ms，而原生解码是独立的一次原图请求（几百 ms 起），时间一到就切「黑底 + 转圈」，图到了再蹦出来                                           | 上限提到 1.5s；Hero 落位后等页面画好再交接（无淡入）；Hero 入场前 20% 淡入，避免在压暗的缩略图上弹出更亮的一块 |
| 首页/详情不能连续翻，会自己滚回去、只能翻一次 | 「一次手势最多翻一页」硬钳制的基准 `settledRef` 在连续快滑时是过期的；另外 `pointercancel` 会在拖动中途把「按着手指」清掉，让程序化滚动/停靠校正抢走手势     | 停用钳制（保留纯函数）；触摸状态按 touch/pointer 两路分开跟踪，两者都结束才算抬手                              |
| 下拉退出阈值太高                              | 提交阈值是屏高 28%                                                                                                                                           | 改为 min(80dp, 屏高 10%) 或快速下滑（>1100 px/s）即关闭                                                        |
| 不能点击退出全屏，要返回两次                  | 没有单击退出；且隐藏导航栏后，手势导航的第一次返回被系统用于「唤出系统栏」                                                                                   | 加 `onSingleTapConfirmed` 单击退出（放大态先缩回 1x）；只隐藏状态栏、导航栏保留透明                            |
| 滑动图片下面的点不跟随更新                    | 索引上报被放在「手指已抬起」之后，触摸状态机一旦没清干净就永久不上报                                                                                         | 每次停靠都上报（拖动中也上报），与触摸状态解耦                                                                 |
| 返回后详情页主轮播与退出时不是同一张          | 右上角关闭按钮走的是不带结果的 `finish()`（索引变 -1）；且索引只在 `onPageSelected`（停稳）时更新；详情→首页那段只比较索引值，连续两次同张会被判成「没变化」 | 关闭按钮走 `finishWithResult()`；计数与返回索引跟随 `onPageScrolled`；回传改为 `{index, seq}` 自增序号         |

## 6. 真机应急开关

`localStorage.k_viewer_hero = 'off'` → 关闭 Hero（退化为淡入），用于快速区分
「是 Hero 的问题，还是查看器本身的问题」。改完刷新页面生效，**不需要重装 APK**。
