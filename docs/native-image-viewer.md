# 原生图片查看器（方案 B）设计与联调清单

> 目标：把「全屏看图」从 WebView 里搬出来，换成和微信朋友圈 / 酷安 / 小红书 /
> 系统相册同一套做法（原生 View + 原生手势），彻底摆脱 WebView 在跟手与掉帧上的天花板。

## 1. 为什么必须做成原生

| 层          | WebView 方案                                 | 原生方案（本实现）                                                       |
| ----------- | -------------------------------------------- | ------------------------------------------------------------------------ |
| 谁搬像素    | Chromium 合成器（原生滚动）/ JS（transform） | RenderThread 直接绘制                                                    |
| 手势 → 画面 | 触摸事件跨到网页层再回写                     | 原生 `ScaleGestureDetector` / `GestureDetector` / `ViewPager2`，无跨语言 |
| 惯性/回弹   | 浏览器滚动物理（上一版才拿到）               | `ViewPager2`/`OverScroller` 原生物理                                     |
| 打开/关闭   | 只能做淡入淡出                               | Hero 共享元素转场 + 下拉关闭                                             |
| 大图解码    | 网页层解码 + 合成层纹理                      | 原生采样解码 + `LruCache`，按屏幕尺寸解                                  |

结论：WebView 已经做到它的上限（见 0.2.42 的原生滚动分页），再往上只有原生。

## 2. 组成

### 原生（`client/android/app/src/main/java/com/k/app/`）

| 文件                           | 职责                                                                         |
| ------------------------------ | ---------------------------------------------------------------------------- |
| `ImageViewerActivity.java`     | 查看器宿主：ViewPager2 翻页、计数、关闭按钮、Hero 打开动画、下拉关闭编排     |
| `ZoomableImageView.java`       | 手势核心：捏合 1x–4x、放大后平移（边缘钳制）、双击缩放、1x 纵向拖拽关闭      |
| `ImageLoader.java`             | 异步采样解码 + `LruCache` + 自定义请求头 + EXIF 方向校正                     |
| `NativeImageViewerPlugin.java` | Capacitor 插件桥：`open({images,index,headers,rect})` → `{index}`、`close()` |

关键设计：

- **缩放与翻页互斥**：放大态 `requestDisallowInterceptTouchEvent(true)`，翻页交还 `ViewPager2`；
  1x 时横向手势不截断，正常翻页。
- **下拉关闭**：仅 1x 且纵向为主时进入，位移跟手、幕布同步变淡，松手超过 1/4 屏即关闭。
- **Hero 打开**：JS 传来被点缩略图的屏幕矩形 → 先在该矩形画这张图，再动画到「等比铺满」目标矩形，
  同时幕布由透明渐入；解码未及时完成则退化为淡入（不阻塞打开）。
- **EXIF**：相机竖拍照片原生解码不校正会躺倒（WebView 是正的），必须处理。

### 网页层

| 文件                                       | 职责                                                                      |
| ------------------------------------------ | ------------------------------------------------------------------------- |
| `client/src/lib/nativeImageViewer.ts`      | 能力探测（仅原生 Android 且插件已注册）+ 调用封装；不可用/失败返回 `null` |
| `client/src/components/post/PostMedia.tsx` | 点击图片/放大按钮时优先走原生；`null` 回退现有 Web 覆盖层                 |

设计要点：

- **可回退**：插件不可用（网页端、桌面）或原生调用抛错 → 自动回退 Web 覆盖层，看图能力不会整体失效。
- **不叠加 UI**：原生接管时不渲染 Web 覆盖层。
- **索引回传**：用户可能在原生里翻过页，关闭后按返回的 `index` 同步详情页主轮播与索引。
- **鉴权**：`/api/` 开头的图片需要 `Authorization`，由 JS 从 `localStorage.k_token` 取出并传给原生
  （`<img>` 无法自定义请求头，原生 HTTP 请求可以）。

## 3. 已覆盖 / 未覆盖

已覆盖：

- 帖子详情的多图全屏查看（`PostMedia`）——多图翻页 + 缩放 + 下拉关闭 + Hero。

暂未覆盖（下一阶段）：

- 聊天图片查看器（`ChatZoomOverlay`）、私密文件夹（`PrivateFolder`）：仍是 Web 覆盖层。
  这两处图片走 `/api/` 鉴权，接入方式与上面一致，但需要真机确认后再切。
- 关闭时的**反向** Hero（飞回缩略图）：目前关闭是「下拉滑出/淡出」。反向 Hero 需要网页层
  提供目标缩略图的实时位置，等首轮真机联调后再加。

## 4. 真机联调清单

装 0.2.44 后请重点确认：

1. **打开**：点详情页图片 → 是否从缩略图位置平滑放大进入（不是黑屏闪一下）；
2. **翻页**：左右滑动是否顺、松手是否精确停在一张（不该停在两张之间）；
3. **缩放**：双指捏合是否围绕手指中点跟手；放大后单指拖动是否只平移图片、不翻页；
4. **双击**：双击放大到 2.5x（以双击点为锚），再双击缩回 1x；
5. **下拉关闭**：1x 时下拉 → 图片跟手、背景变淡，松手超过约 1/4 屏即关闭；不足则回弹；
6. **EXIF**：相机竖拍的照片是否正立（这是原生解码最容易躺倒的地方）；
7. **鉴权图**：私信/私密图片若已切原生，是否正常加载（未切则为 Web，不受影响）；
8. **返回键**：原生查看器里按返回是否正常关闭，且回到详情页时主轮播停在最后看的那张；
9. **失败退化**：弱网/超大图时是否显示「图片加载失败」，且不崩不卡死。

已知风险（首轮重点关注）：

- `ViewPager2` 与自绘手势的边界（放大态翻页、1x 时纵向拖动）在部分机型上可能过灵/过钝；
- Hero 的起始矩形依赖 `WebView.getScale()`，若某机型返回异常值，表现为「从错误位置放大」——
  不影响功能，可先在插件里把 `rect` 置空验证；
- 完整 GIF/动图在原生侧按静态图解码（WebView 会动），如有需求再单独处理。
