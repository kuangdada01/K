## 0. 通用规则（每条都必须遵守）

1. **拆分先「纯搬移」再「小步修 bug」**：一个 PR 只做结构移动，行为逐字节不变；修 bug 另起提交。
2. **行为不变量**：导出名、props、事件名与 payload、toast 文案、动画时序、网络请求时机全部不变。
3. **每批结束跑全部门禁**（见 §6），绿了再进下一批。
4. 行号提示：本文给的行号基于拆分前源码，**已经过一轮拆分，实际行号会偏移**——一律用 `grep` 按函数名/注释关键词定位，不要死磕行号。
5. 涉及 WebRTC / 上传 / 手势的改动，改完必须走 §6 的 e2e 或真机回归，不要只信 tsc。

### 1.1 `CreatePost.tsx` 媒体草稿层（当前约 850 行，已拆出 `useComposerLifecycle`）

**目标结构**

```

  useMediaDraft.ts          # 图片/视频选择、大小校验、HEIC 预览、blob 生命周期、9 图截断、拖拽顺序
  useVideoCoverCapture.ts   # 视频封面 canvas 截帧、seek 超时、loadeddata 判定、coverTime
client/src/components/post/
  MediaPickerStep.tsx       # step1「选择媒体」UI + 图片网格/轮播预览
  CreatePost.tsx            # 退化为三步状态机 + 提交编排 + 组合上述 hook/组件
```

**步骤**

1. `useMediaDraft`：搬移 `images/videoFile/videoPreview/videoCoverFile/videoCoverPreview` 相关 state、`handleFileSelect`（含 9 图 `slice(0,9)` 截断）、`handleRemoveImage`（blob revoke）、`handleVideoSelect`（300MB 上限、blob URL 创建与统一回收）、`handleRemoveVideo`。**关键不变量**：blob URL 的 revoke 时机（卸载兜底 + 替换时）必须完全一致；`videoFile` 与 `images` 的互斥（选图清视频、选视频清图）。
2. `useVideoCoverCapture`：搬移 `extractFrame`（720p 画布限制、同值 seek 已停在目标帧则直接截取）、`handleVideoLoaded`（300ms 判定 + 大文件 150MB 标记）、`handleVideoError`、`handleCoverTimeChange`、`handleCoverFileSelect`。**已知待修 P2**：`extractFrame` 的 300ms 定时器在卸载后未清理（搬移时用局部 sink 引用清理，行为不变）。
3. `MediaPickerStep.tsx`：只搬 JSX（`renderGrid` 及 step1 区块），props 注入 state 与 handler。
4. `CreatePost.tsx` 保留：`step` 状态机、`handleContinue/handleBack`、`handleSubmit`（FormData 组装、分片/普通上传、进度）、`useComposerLifecycle` 组合。

**验证**：`npm run build --prefix client` + §6 全部门禁 + 手动走一遍「选图 → 拖拽排序 → 发帖」和「选 HEIC → 自动转预览 → 发帖」。

## 2. 阶段 3B：服务端拆分

> 服务端已有 routes/repositories 分层，本次只做「编排逻辑 vs 路由绑定」的进一步分离。

### 2.1 帖子写路径 service 化

**目标**

```
server/src/services/post.service.ts       # createPost/updatePost/deletePost 编排：校验→压缩→入库→按结果删文件
server/src/lib/chunkUploadRegistry.ts     # 分片上传会话注册表（从 routes/posts/media.ts 抽离）
server/src/routes/posts/crud.ts           # 只做参数解析 + 响应映射
server/src/routes/posts/media.ts          # 只做 multer 绑定 + 调用 service/registry
```

**步骤**
1. `chunkUploadRegistry`：把 `media.ts` 里的 `chunkUploadOwners` Map、`pruneChunkUploads`、`TEMP_VIDEO_NAME_RE`、`MAX_VIDEO_BYTES` 等常量搬进去，导出 `acquireChunkUpload/verifyOwner/releaseChunkUpload/prune`。
2. `post.service.ts`：把 `crud.ts` 的 `POST /`、`PUT /:id`、`DELETE /:id` 里的副作用编排（multer 文件清理、压缩、入库、`syncPostTags`、`removedOldImages` 计算）搬入。**顺带修 §5.1 的 keepImages 白名单校验与压缩失败孤儿文件清理**。
3. 路由只留 `authMiddleware` + `imageUpload.array('images', 9)` + `asyncHandler(() => postService.createPost(...))`。

**关键不变量**：失败路径「已落盘 multer 文件必须清理」；`DELETE` 的「先收集文件引用 → 删库 → 删文件」顺序。
